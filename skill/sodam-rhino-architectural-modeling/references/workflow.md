# Workflow and component contract

The skill is an agent workflow, like the upstream Mode A skill. The agent interprets the user's photo, brief, drawings, and dimensions. The local MCP writes files; it does not infer hidden geometry from pixels on its own.

Call `get_architectural_workspace` for the actual workspace path. Tool file arguments are simple names inside that folder. Do not pass absolute paths or `..` to the MCP. Preserve source photos and existing models; use a new filename for each revision.

Use `write_architectural_spec` to save a validated JSON object in the MCP workspace when the agent cannot write that folder directly. Never overwrite a user-authored spec; choose a new filename. Write a JSON object with `units` (`meters`, `millimeters`, `centimeters`, or `feet`) and a nonempty `components` list. Each component needs `kind`, `name`, `layer`, `origin` `[x,y,z]`, `size` `[dx,dy,dz]`, and `evidence` (`given`, `measured`, or `inferred`). Optional `color` is integer RGB. Supported `kind` values are `box`, `wall_opening`, `gable_roof`, and `cylinder` (vertical round column, equal X/Y diameters, 12–256 segments). For a wall opening include `axis` (`x` or `y`) and `opening` with `start_bottom` `[horizontal start,bottom]` and `size` `[width,height]`. A gable roof needs positive `ridge_height`. See the repository's `examples/small_house.json` for a complete example.

For a non-photo component revision, `revise_architectural_spec` takes a saved JSON filename, exact component name, complete replacement component JSON, and a fresh output JSON filename. It preserves all other components and never overwrites. Build the resulting new `.3dm`. The tool rejects evidence-tagged specs so changed numbers cannot keep stale photo provenance; create a new full spec and repeat the evidence audit for those cases.

For a photo case, call `prepare_architectural_reference` to record file hashes and independently known dimensions, then `draft_architectural_evidence`. Inspect and correct every numeric field's provenance; the draft deliberately marks all values as inferred. `audit_architectural_evidence` checks provenance completeness and source integrity, not geometric accuracy. Use `build_verified_architectural_model` only when the evidence audit passes. The returned `accuracy_verified=false` remains authoritative. For a brief without photos, use `build_architectural_model` and state the missing image check.

After building, call `inspect_architectural_model` and compare units, bounds, layers, and component names against the brief. Use two cameras showing different sides. `render_blender_model` accepts front_azimuth/front_elevation and rear_azimuth/rear_elevation in degrees (defaults 315/28 and 135/28); views less than 10 degrees apart are rejected. The `.blend` stores these cameras, but the mesh-based `.3dm` does not gain named Rhino views. Compare rendered perspective with the reference before claiming alignment. Check `blender_executable_configured` in `get_architectural_workspace`: when true, use `render_blender_model` for the final two material views and saved editable `.blend`. When false, `render_architectural_view` provides orthographic inspection views only; report the missing final render capability. A configured path is not proof that Blender completed a render, so check the tool result and actual files.

For shapes beyond these JSON component kinds, model in Blender and call `import_blender_scene` on a trusted `.blend` in the MCP workspace. This exports evaluated mesh geometry with object names, collection layers, and basic material colors; retain the `.blend` for editing. Confirm Blender scene units or pass meters_per_blender_unit, then reopen and render the `.3dm`. If a requested shape or editing behavior still exceeds the supported mesh workflow, report the exact gap. Do not silently approximate a defining form. The JSON-built `.3dm` contains named meshes and control JSON; the Blender-imported `.3dm` contains named meshes and Blender source metadata, while the editable source remains `.blend`. Neither path provides Rhino-native NURBS solids or Rhino's live document state.
